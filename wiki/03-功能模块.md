## 派系与声望

### faction-manager.js — 增强购买规划器（1009 行，需 SF4）

周期性盘点所有派系与 augmentation，回答"现在重置能买到哪些增强"。

- **数据建模**：`AugmentationData` 保存每个 aug 的名称、声望需求、价格、stats、prereqs（[L425-L478](../faction-manager.js)）
- **数据收集**：`getAugmentationsFromFaction / getFactionRep / getFactionFavor / getAugmentationPrice / getAugmentationRepReq / getAugmentationStats / getAugmentationPrereq` 建立全局信息表（[L307-L415](../faction-manager.js)）
- **购买来源选择**：`getFromJoined()` 在已加入派系中按最低成本（购买价 + 捐赠换声望成本）选出售方；NeuroFlux Governor 特殊排序
- **排序**：`sortAugs` 按价格、声望、desired 状态与依赖关系（先买前置）生成购买顺序（[L541-L607](../faction-manager.js)）
- **`--purchase`**：按预算、优先级、缺失前置计算 `purchaseableAugs` 与需要捐赠的派系，执行购买（[L714-L840](../faction-manager.js)）
- 价格通胀：游戏中每买一个 aug，其余涨价——脚本在规划时模拟这一过程
- 关键参数：`--ignore-faction`、`--force-join`、`--priority-aug`、`--omit-aug`、`--stat-desired`、`--neuroflux-disabled`、`--disable-donations`、`--sort`、`--unique`

### work-for-factions.js — 焦点工作管理器（1302 行，需 SF4）

管理玩家唯一的"focus"动作：为派系/公司工作、上大学、犯罪，以刷声望/邀请/属性。

- 派系优先级表：`preferredEarlyFactionOrder`、`preferredCompanyFactionOrder`、`preferredCrimeFactionOrder`（[L65-L96](../work-for-factions.js)）
- 主循环（[L947-L1020](../work-for-factions.js)）：检测工作是否被打断 → `detectBestFactionWork`（[L1047-L1071](../work-for-factions.js)，实测各 `FactionWorkType` 的声望速率选最优）→ `startWorkForFaction` 并估算 ETA
- 犯罪逻辑 `crimeForKillsKarmaStats`（[L618-L668](../work-for-factions.js)，被 `crime.js` 复用 import）：按 `--fast-crimes-only`、成功概率、Karma/击杀需求选择犯罪
- 大学课程：`ns.singularity.universityCourse`（[L679-L698](../work-for-factions.js)）
- 资金超过阈值时用 hash 买 coding contract 刷声望（[L1110-L1119](../work-for-factions.js)）
- 关键参数：`--fast-crimes-only`、`--prioritize-invites`、`--get-invited-to-every-faction`、`--invites-only`、`--no-crime`、`--no-studying`、`--no-coding-contracts`

### crime.js — 纯犯罪循环（37 行，需 SF4）

两种模式：指定单一犯罪跑简单循环（`legacyAutoCrime`），或不带参数/`--fast-crimes-only` 时委托给 `work-for-factions.js` 导出的 `crimeForKillsKarmaStats` 智能选罪。

### farm-intelligence.js — 刷智力（30 行，需 SF4+SF5）

利用"软重置刷新派系邀请"机制：生成一个微型临时脚本，在紧循环里 `joinFaction` 全部邀请 → `softReset` → 重复，以此刷 intelligence 经验。运行前要求距上次重置 < 20 分钟（防止误清进度）。

## 子系统经营

### gangs.js — 帮派管理（604 行，需 SF2）

- 主循环按 `updateInterval` 运行（[L71-L89](../gangs.js)）；领土 tick 时招募、升级装备、切换领土战（[L222-L252](../gangs.js)）
- **任务优化器**（[L281-L368](../gangs.js)）：计算每个成员在每个任务上的 respect/金钱/wanted 期望收益，贪心 + 随机 shuffle 搜索近似最优分配；wanted 过高时自动切降通缉任务
- `doRecruitMember` 招募、`tryAscendMembers` 按属性倍率阈值晋升、`tryUpgradeMembers` 按 `--augmentations-budget`/`--equipment-budget` 买装备（[L390-L462](../gangs.js)）
- 关键参数：`--training-percentage`、`--ascend-multi-threshold`、`--money-focus`、`--reputation-focus`

### sleeve.js — 分身管理（446 行，需 SF10）

`pickSleeveTask`（[L217-L355](../sleeve.js)）按优先级为每个分身选任务：**同步 → shock 恢复 → 训练（`--train-to-*`）→ 学习（`--study-to-*`）→ 跟随玩家派系/公司工作 → 帮派凶杀 → bladeburner 行动 → 犯罪**；任务变化时 `setSleeveTask` 下发。另按 `--aug-budget` / `--min-aug-batch` / `--buy-cooldown` 为分身购买增强。

### bladeburner.js — 刀锋战士（457 行，需 SF7）

- 主循环（[L134-L174](../bladeburner.js)）：获取 rank → 加入 bladeburner 派系 → 消费 skill points → 统计 contracts/operations/blackops 剩余与 `--reserved-action-count`
- action 选择（[L240-L316](../bladeburner.js)）：综合 stamina 区间（`--low-stamina-pct` / `--high-stamina-pct`）、chaos（`--chaos-recovery-threshold` / `--max-chaos`）、raid、population、成功率阈值选择最优 action；不满足时回退到 general action / field analysis / training
- 执行切换（[L318-L354](../bladeburner.js)）：比较当前与目标 action，必要时取消重启
- 联动：自动启动 `spend-hacknet-hashes.js` 用 hash 换 rank/SP（[L367-L458](../bladeburner.js)）

## 赚钱

### stockmaster.js — 股市自动化（1043 行）

- 主循环每秒刷新持仓与行情：先卖出预期收益不达标或预测反转的仓位，再按 `getTicksToCoverSpread`（回本 tick 数）、`calcAbsReturn`、`getSignalWeight` 与分散化预算排序买入
- **双阶段预测**：无 4S 数据时用价格波动统计估概率（`--pre-4s-*` 系列阈值）；有 4S 后直接读官方 forecast（`--buy-4s-budget` 控制何时购买 4S）
- `detectInversion` 检测市场周期反转
- 关键参数：`--fracB`（买入资金比例）、`--fracH`（持有现金比例）、`--liquidate/-l`（清仓退出，重置前用）、`--reserve`
- 与 daemon 的 `--stock-manipulation` 联动：hack 压低做空目标的股价、grow 抬升做多目标

### casino.js — 赌场 21 点（604 行）

**save-scumming 自动化**：导航到 Aevum 赌场 → 保存游戏 → 循环下注（`--use-basic-strategy` 基础策略决策 Hit/Stay）→ 赢则 `saveGame` 锁定利润，输则 `reload` 读档回滚。纯 DOM 自动化：点击按钮、读文本，参数 `--click-sleep-time` / `--find-sleep-time` / `--save-sleep-time` 控制节奏。赢满 10b 或被踢出后执行 `--on-completion-script`。辅助函数：`checkForStolenFocus`、`checkStillAtCasino`、`checkForKickedOut`、`getWinLoseOrTie`。

### go.js — IPvGO 围棋（1570 行）

自动在子网路由器上下 IPvGO 刷全属性倍率。主循环 `playGo` 每回合读 `ns.go.getBoardState` / `getValidMoves` / `getLiberties` / `getChains` / `analysis.getControlledEmptyNodes`，**按对手派系切换策略**（Netburners / The Black Hand / Slum Snakes 等风格不同）：`getOpeningMove` 开局、`getRandomCounterLib`/`getSnakeEyes`/`disruptEyes` 破眼、`attackGrowDragon` 攻杀。支持作弊辅助（`--cheats`，默认开，`--cheat-chance-threshold` 控制成功率阈值），如 `go_cheat_playTwoMoves`。`--runOnce` 只下一盘。

## Hacknet

### hacknet-upgrade-manager.js（149 行）

回本时间（payoff time）模型：对 level/ram/cores/cache 四种升级与新购节点分别算 `addedProduction / cost`（[L65-L124](../hacknet-upgrade-manager.js)），在 `--max-payoff-time` 内选最优执行（[L131-L149](../hacknet-upgrade-manager.js)）。`--max-spend` 限制单次花费，`--continuous` + `--interval` 常驻。daemon 以 4h/8h/∞ 三档回本时间各挂一个实例，对应不同资金量级。

### spend-hacknet-hashes.js（235 行，需 SF9）

按 `--spend-on` 优先级列表（如 `Sell_for_Money`、`Exchange_for_Bladeburner_Rank`、`Generate_Coding_Contract`、`Increase_Maximum_Money`…）循环消费 hash（[L78-L117](../spend-hacknet-hashes.js)）；`--liquidate` 模式只换钱（重置前用）。容量将满时自动比较"买新节点 vs 升 cache"扩容（[L142-L189](../spend-hacknet-hashes.js)），`--no-capacity-upgrades` 可关闭。
