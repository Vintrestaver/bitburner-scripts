## daemon.js — 黑客调度守护进程（2364 行）

仓库最核心、最复杂的脚本。负责把"黑掉整个网络并持续变现"这件事完全自动化。

### 职责

1. 扫描全网，用已有端口破解器 root 尽可能多的服务器
2. 评估所有已 root 服务器的**单位时间收益**，选出 hack 目标
3. 计算 HGW 批周期参数，把 `Remote/` worker scp 到各服务器并按时间片 exec
4. 拉起并托管全部子系统脚本（异步助手 + 周期任务）
5. 可选：配合股市做多/做空操纵、XP 刷级、share 声望增益

### 关键参数（argsSchema，[daemon.js#L20-L74](../daemon.js)）

| 参数 | 默认 | 含义 |
|---|---|---|
| `--looping-mode` | false | worker 长生命周期循环模式（末期高 hack 等级用） |
| `--stock-manipulation` / `--stock-manipulation-focus` | false | hack/grow 联动股价操纵 |
| `-x` / `--xp-only` | false | 只刷 hack 经验（隐含 `--no-share`） |
| `--cycle-timing-delay` / `--queue-delay` | 1000 / 200ms 级 | 批周期与批内操作间隔 |
| `--recovery-thread-padding` | 1 | grow/weaken 恢复线程倍数，looping 模式下自动提到 10 |
| `--no-share` / `--no-tail-windows` | false | 关闭 share 利用 / 不弹 tail 窗口 |
| `--disable-script` | [] | 禁止 daemon 启动指定子脚本 |
| `--run-script` | [] | 额外追加要常驻的脚本 |
| `--initial-max-targets` | — | 初期并行目标上限 |

### 启动的两个脚本清单（[daemon.js#L358-L435](../daemon.js)）

**asynchronousHelpers（常驻，只启动一次）：**

| 脚本 | 启动条件 |
|---|---|
| `stats.js` | home RAM ≥ 64GB |
| `go.js` | home RAM ≥ 64GB（动态 RAM 需求 ~20GB） |
| `stockmaster.js` | home RAM ≥ 64GB |
| `hacknet-upgrade-manager.js` | hacknet 收益未被 BN 禁用且有余钱（1h 回本 kickstart） |
| `spend-hacknet-hashes.js` | 拥有 SF9 |
| `sleeve.js` | 拥有 SF10 |
| `gangs.js` | 拥有 SF2 |
| `work-for-factions.js` | 拥有 SF4 且 RAM 足够 |
| `bladeburner.js` | 拥有 SF7 且 BN 未禁用 bladeburner 晋升 |

**periodicScripts（每 ~25–33s 错峰轮询一次）：**

`tor-manager` → `program-manager` → `contractor` → `hacknet-upgrade-manager ×3`（4h/8h/∞ 回本三档预算）→ `ram-manager`（50% 预算升 home RAM）→ `faction-manager` → `host-manager` → `backdoor-all-servers`

### 主循环（[daemon.js#L700-L851](../daemon.js)）

每轮迭代依次：刷新服务器列表与 root 状态 → 更新端口破解器库存 → 刷新玩家信息 → 启动到期辅助脚本 → 重算目标优先级 → 按 `root → prep（把目标 grow/weaken 到健康态）→ target（正式批循环）→ skip/cap` 分配工作。

### 调度执行（[daemon.js#L1647-L1661](../daemon.js)、[L1817-L2005](../daemon.js)）

- 远程执行前先 `scp` 补齐缺失的 worker 与 `helpers.js` 依赖
- 普通模式按 RAM 把目标匹配到主机；looping 模式下目标**锁定**到主机避免频繁切换
- 单次周期调度：选工具（hack/weak/grow）→ 算线程数 → 套用 queue-delay 与恢复线程 → `arbitraryExecution` 下发 `start_time/duration` 参数

### 值得注意的机制

- **股市联动**：`--stock-manipulation` 让 worker 的 `hgwOptions.stock = true`，hack 压价 / grow 抬价，与 `stockmaster.js` 持仓方向配合
- **misfire**：worker 启动晚于 `start_time` 或 hack 偷到 0 即视为 misfire（`ns.toast` 警告），由恢复线程负责把目标拉回健康状态
- **多实例友好**：daemon 只在脚本未运行时拉起它；玩家想自定义参数，可在 daemon 之前先手动跑

## helpers.js — 共享工具库（961 行）

几乎所有脚本的 import 来源，全仓库的"公共底盘"。完整 API 参考见 [05-关键类与函数](05-关键类与函数.md)。

### 六大职能

| 类别 | 代表函数 | 说明 |
|---|---|---|
| 参数/配置 | `getConfiguration` (L814) | **三级优先级**：命令行 > `script.js.config.txt` > argsSchema 默认值；`--help` 自动生成帮助 |
| 格式化/日志 | `formatMoney` (L7)、`formatDuration` (L74)、`log`、`disableLogs` (L104)、`tail` | `$6.50M`、`1h 21m` 风格输出；统一日志级别与颜色 |
| 网络工具 | `scanAllServers` (L566) | `ns.scan` 递归遍历全网 |
| 低 RAM 执行 | `getNsDataThroughFile` (L144)、`runCommand` (L323)、`runCommand_Custom` (L353) | 见 [架构 §5](01-整体架构.md#5-ram-经济学getnsdatathroughfile-模式) |
| 进程管理 | `instanceCount`、`getRunningScript`、`waitForProcessToComplete` | 单实例保护与进程等待 |
| 资金控制 | `parseShortNumber`、reserve 读取相关 | 解析 `100m` 这类缩写；配合 `reserve.txt` |

### 临时文件约定

`getDefaultCommandFileName` (L210) 把 `ns.namespace.func(args)` 映射为 `/Temp/namespace-func.txt`——这就是 `/Temp/` 目录数百个小文件的来源。

## autopilot.js — 总编排器（1160 行）

"替你做游戏层面决策"的脚本：监控进度、安排子系统、决定何时重置。

### 关键参数（[autopilot.js#L7-L31](../autopilot.js)）

`--next-bn`（指定下一个 BitNode）、`--install-countdown`（重置倒计时）、`--disable-casino`、`--on-completion-script`（BN 完成后运行）、自动安装增强的数量/成本阈值等。

### 主循环（[autopilot.js#L241-L254](../autopilot.js)）

每轮依次：读玩家状态 → 更新缓存 → 管理 reserve 预留金 → 检查 Daedalus 进度 → **检测 BN 完成条件** → 接受 Stanek 礼物 → 检查/启动各子系统 → 可选跑 casino → 判断是否该安装增强。

### 子系统调度（[autopilot.js#L503-L660](../autopilot.js)）

按 BN、RAM、hack 等级、XP 模式等条件启停 `stockmaster / sleeve / spend-hacknet-hashes / daemon / stanek`；典型例子：检测到 hack 等级足够高时，**以 `--looping-mode` 高性能参数重启 daemon**（若已在 looping 则不打扰）。

### BN 完成与重置（[autopilot.js#L367-L470](../autopilot.js)、[L819-L968](../autopilot.js)）

- 检测 hack 胜利（hack `w0r1d_d43m0n`）或 bladeburner 胜利条件
- 读取 `faction-manager.js` 的输出计算可负担增强数量/成本
- 处理 BN8/BN9/Daedalus 等特殊延迟逻辑
- 条件满足 → 启动 `ascend.js --install-augmentations` → `singularity.destroyW0r1dD43m0n` 进入下一 BN
- 默认 BN 推进顺序见 `defaultBnOrder`（[L47-L81](../autopilot.js)），按解锁收益/难度排序

## ascend.js — 重置流程自动化（208 行）

重置（install augmentations / soft reset）前所有"该做但容易忘"的事的清单执行器。

### 参数（[ascend.js#L6-L18](../ascend.js)）

`--install-augmentations`、`--reset`（软重置）、`--allow-soft-reset`、`--skip-staneks-gift`、`--prioritize-home-ram`、`--on-reset-script`。

### 流程

```
终止其他脚本、停止当前 action、清空 reserve.txt
  → 清算 stockmaster 持仓 + spend-hacknet-hashes 变现（--liquidate）
  → 可选优先升级 home RAM（--prioritize-home-ram）
  → 处理 Stanek's Gift（除非 --skip）
  → 启动 faction-manager.js --purchase 买增强
  → 检查并购买 4S 股市数据/API
  → ns.singularity.installAugmentations() 或 softReset()
  → （重置后）自动启动 stanek.js / daemon.js
```

入口要求 SF4；执行前先杀光其他脚本以集中 RAM 与资金（[ascend.js#L28-L50](../ascend.js)），购买完成后由 [L195-L208](../ascend.js) 触发真正的 reset。
