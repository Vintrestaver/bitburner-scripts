## 根目录基础设施

### host-manager.js — 私人服务器购买/升级（243 行）

- 入口（[L40-L95](../host-manager.js)）：`getConfiguration` 读参 → 单实例检查 → 读 `reserve.txt` → `--run-continuously` 时周期执行 `tryToBuyBestServerPossible`
- 资源评估（[L104-L135](../host-manager.js)）：扫描已 root 服务器与已购服务器（排除 hacknet 节点 RAM），`totalUsedRam / totalMaxRam` 与 `--utilization-trigger` 决定是否需要扩容
- 购买决策（[L157-L220](../host-manager.js)）：算可花金额 → 选最大可负担 RAM 档位 → 校验 `--min-ram-exponent`、`--compare-to-home-threshold`、`--compare-to-network-ram-threshold` → 达到购买上限时升级最弱服务器
- daemon 以 `--reserve-by-time` 调用它：在 BN 内停留越久保留越多资金（24h 后保留 ~92%）

### scan.js — 网络可视化（158 行）

增强版 `scan-analyze`（[L16-L87](../scan.js)）：递归遍历全网，显示每台服务器的 root 状态、可 hack 标记、RAM/金钱/安全统计、发现的 coding contracts，并提供 backdoor 跳转链接。深度不限。

### analyze-hack.js — 收益排行（199 行）

用 `ns.formulas.hacking` 计算每个目标的 weaken/grow/hack 成本、窃取百分比、理论收益率与经验率（[L56-L93](../analyze-hack.js)，无 formulas 时回退实测），按收益或 XP 排序输出并写 `/Temp/analyze-hack.txt`（[L124-L184](../analyze-hack.js)）。

### stats.js — HUD 状态增强（368 行）

常驻，往游戏 HUD 追加额外信息（当前收入速率、份额、各类进度），home RAM ≥ 64GB 时由 daemon 自动拉起。

## Remote/ — 远程 Worker（部署到目标服务器执行）

由 daemon `buildToolkit` 注册（[daemon.js#L425-L435](../daemon.js)），`scp` 到目标机后 `exec`（[daemon.js#L1647-L1661](../daemon.js)）。统一参数协议：`[target, start_time, duration, description, manipulateStock, silentMisfires, loopingMode]`。

| 脚本 | 行数 | 说明 |
|---|---:|---|
| `hack-target.js` | 42 | 到点执行 `ns.hack(target, {stock, additionalMsec})`；迟到/零收益报 misfire；looping 模式按 `duration × 4`（weaken 周期）循环 |
| `grow-target.js` | 43 | 同上，执行 `ns.grow`，恢复目标金钱；含 misfire 检测与 looping 对齐 |
| `weak-target.js` | 38 | 同上，执行 `ns.weaken`，降低安全等级；允许 `threadSpreadingAllowed` 跨机拆线程 |
| `manualhack-target.js` | 18 | 用 `ns.singularity.manualHack()` 执行（吃 manual hack 加成场景） |
| `share.js` | 3 | 仅 `ns.share()` 循环，吃空闲 RAM 换声望增益 |
